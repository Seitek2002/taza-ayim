# Деплой taza-ayim.kg

**Обычный случай: ничего делать не нужно.** Пуш в `master` сам обновляет сайт
примерно за 1–3 минуты. Ход деплоя: вкладка **Actions** в GitHub → **Deploy**.

## Как это устроено

1. GitHub Actions подключается к серверу по отдельному SSH-ключу (секрет
   `DEPLOY_SSH_KEY`). На сервере этому ключу разрешена **только** команда
   `taza-ayim-deploy`: ни шелла, ни других команд.
2. Скрипт [deploy.sh](deploy.sh) (на сервере: `/usr/local/bin/taza-ayim-deploy`)
   забирает свежий `master` и собирает Docker-образ. Пока идёт сборка,
   сайт работает на старой версии.
3. Новая версия запускается рядом со старой: два слота, **blue** (порт 3020) и
   **green** (3021). Если `/ru` и `/ky` отвечают 200, nginx мягко переключается
   на неё, а старая останавливается и хранится для отката.
4. Если сборка или проверка не прошли, переключения нет и сайт остаётся на
   прежней версии. Деплой в Actions будет красным, причина в его логе.

Изменения только в `*.md` и `docs/` деплой не запускают.

## Откатить

GitHub → **Actions** → **Deploy** → **Run workflow** → выбрать `rollback`.
Сайт за несколько секунд вернётся на предыдущую версию. Это временная мера:
следующий пуш в `master` снова задеплоит свежий код, поэтому ошибку нужно
исправить (или сделать `git revert`) и запушить.

## Вручную на сервере

```bash
ssh root@217.114.0.30
taza-ayim-deploy status     # что сейчас работает
taza-ayim-deploy deploy     # задеплоить свежий master
taza-ayim-deploy rollback   # откат
```

Лог всех деплоев: `/var/log/taza-ayim-deploy.log`.

## Если меняете deploy.sh

Сервер использует копию скрипта, поэтому после правок её нужно обновить:

```bash
scp deploy/deploy.sh root@217.114.0.30:/usr/local/bin/taza-ayim-deploy
```

## Важно: сервер общий

На `217.114.0.30` живут ещё ~10 чужих проектов. nginx применяйте только через
`nginx -t && systemctl reload nginx`, никаких `restart`. Не трогайте чужие
контейнеры и не запускайте глобальные `docker system prune`.
